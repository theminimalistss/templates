# 2026-10-14 — Hostinger static export (0.2.1)

## Summary

The previous npm commands ran Vinext/Cloudflare Workers, including a Wrangler-only production preview. The old build succeeded on the existing local installation, but produced a Worker bundle rather than a directly uploadable website. Switched the default workflow to native Next.js static export for Hostinger's PHP/HTML hosting.

## Changes

- Native `next dev --webpack` on 5173 and `next build --webpack`, using the existing pinned Next/React versions.
- `output: 'export'`, trailing-slash directory indexes and pre-optimized local media. Generated output lives in `out/`.
- `npm start`/`npm run preview` serve the exported files on 4173.
- Removed unused Worker, connector and D1 scaffolding/dependencies. Existing venue components, copy, media and animations were not changed.
- Added export verification, cross-platform ZIP packaging with fflate, a minimal Hostinger `.htaccess`, Node 22 `.nvmrc`, deployment instructions and updated architecture notes.
- Version synchronized to 0.2.1 in VERSION/package.json/package-lock.json.
- `AGENTS.md` and `CLAUDE.md` were generated by native Next.js on the first dev run. Retained their framework guidance; the relevant installed static-export docs match the configuration.
- `.openai/hosting.json` remains a historical identifier, not an active build input. The old Sites deployment was not changed; the requested target is Hostinger.
